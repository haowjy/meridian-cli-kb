# Codebase Vocabulary

Terms covering harness infrastructure, hooks and plugins, safety and permissions, the launch system, state management, config loading, and platform abstractions. For the full vocabulary index see [../vocabulary.md](../vocabulary.md).

| Term | Definition | See also |
|---|---|---|
| **Artifact** | A file produced by or for a spawn, stored under `~/.meridian/projects/<project-id>/spawns/<id>/`. Canonical artifacts: `prompt.md`, `report.md`, `stderr.log`, `params.json`, `tokens.json`. The former runner event stream `history.jsonl` is no longer written (PR 3) and was never a transcript source after PR 2 ([native-only history](../decisions/native-only-history.md)). The published `state.json` row owns the artifact directory's lifetime; missing publication never authorizes recreation. | [../concepts/spawn-lifecycle.md](../concepts/spawn-lifecycle.md) |
| **Artifact store** | Retired duplicate storage under runtime `artifacts/<spawn-id>/`. Identity-v2 PR 5 (#677) deleted its `LocalStore`/`InMemoryStore` protocol and readers; per-spawn files now live only in `spawns/<id>/`. Legacy directories are considered only by cleanup code. | [../architecture/state-system/overview.md](../architecture/state-system/overview.md), [session archive pruning](../operations/session-archive-pruning.md#runner-history-prune) |
| **Bootstrap doc** | A markdown document loaded into primary session prompts at launch. Discovered from `.mars/skills/<name>/resources/BOOTSTRAP.md` (tier 1) and `.mars/bootstrap/<name>/BOOTSTRAP.md` (tier 2), loaded in deterministic order. | [../concepts/bootstrap-docs.md](../concepts/bootstrap-docs.md) |
| **Agent copy** | A Mars `[settings.meridian.agent_copy] harnesses = [...]` setting that materializes Meridian-authored agent profiles into a harness's native agent surface (for Claude, `.claude/agents/`) when that harness is also a Mars target. `agent_copy_enabled(project_root, harness_id)` in `catalog/agent_copy.py` reads it at bind; when true, Meridian leaves that harness's sub-agent tool usable because the native surface is Meridian-owned. | [../concepts/harness-abstraction.md](../concepts/harness-abstraction.md#claude-native-agent-routing), [../decisions/tool-permissions.md](../decisions/tool-permissions.md) |
| **Budget** | An execution cost limit with `per_run_usd` and `per_space_usd` fields. Enforced at runtime by `LiveBudgetTracker`. | [architecture/sandbox-projection.md](../architecture/sandbox-projection.md) |
| **Builtin hook** | An in-process hook implementation (not a shell command) exposing `name`, `requirements`, `default_events`, `supported_events`, `default_interval`, `identity_options` and `execute()`. Currently `git-autosync` and `notify`. | [../concepts/hooks-and-plugins.md](../concepts/hooks-and-plugins.md) |
| **Composition surface** | Alias for **Launch surface**. See that entry. | [../architecture/launch-system.md](../architecture/launch-system.md) |
| **Context** | Disambiguation: (a) **filesystem context** — resolved paths to work directory, KB, and archive; (b) **launch context** — the `LaunchContext` dataclass produced by the composition factory. Disambiguated by surrounding usage. | [../concepts/context-resolution.md](../concepts/context-resolution.md) |
| **Continue replay contract** | Launch-owned normalized contract for exact continue. `continue_replay.py` builds `ContinueReplayContract` from a resolved source reference plus optional `LaunchPolicySnapshot`; primary and spawn continue both consume it instead of independently re-deriving identity, work, task cwd, passthrough args, or session metadata. | [../concepts/session-initiation.md](../concepts/session-initiation.md) |
| **Continue sweep** | `launch/continue_sweep.py:sweep_before_continue()`, run on every continue path before any harness starts (#647). It takes the source's launch lock: held → refuse; free → kill the dead launch's leftover birth-verified scopes. An old spawn ID first resolves to its chat's current owner. | [../architecture/process-scope.md](../architecture/process-scope.md#continue-sweep) |
| **Built-in agent denial** | A platform rule denying a harness's bundled agents (Claude's `Explore`, `Plan`, `General-purpose`; Codex's multi-agent feature). On by default; `[harness.<id>] allow_builtin_agents = true` removes it. | [../concepts/harness-abstraction.md](../concepts/harness-abstraction.md#claude-native-agent-routing), [../decisions/tool-permissions.md](../decisions/tool-permissions.md) |
| **Context source type** | Enum for how a context path is resolved: `local` (resolved relative to project root or absolute) or `git` (resolved relative to a managed git clone of the configured remote). | [../concepts/context-resolution.md](../concepts/context-resolution.md) |
| **Delegation preference guidance** | System-prompt text rendered by Mars into the `prompt_surface.inventory_prompt` bundle field (adjacent to the `# Meridian Agents` list). Tells Claude-hosted primary sessions to use `meridian spawn` for subagent delegation and reserve native `Agent` only for explicit Claude-native/model-specific cases. Meridian embeds the Mars-rendered string verbatim — no Python-side guidance renderer. | [../concepts/composition-pipeline.md](../concepts/composition-pipeline.md#agent-inventory-prompt) |
| **Decline** | A locked mutator's typed decision to preserve the current state: `Decline(reason)`. Returned instead of a `SpawnRecord` when a mutation is refused (e.g., lifecycle violation). The repository wraps the outcome into `Declined(snapshot, reason)`. Replaces four ad-hoc exception classes. | [../architecture/spawn-finalization.md](../architecture/spawn-finalization.md) |
| **Driving adapter** | One of the three top-level entry paths that construct a `SpawnRequest` and `LaunchRuntime`, then compose through the prepare/bind seam. The three: primary CLI path, spawn subprocess path, CLI streaming-serve path. None re-implement composition logic. | [../architecture/launch-system.md](../architecture/launch-system.md) |
| **EARS** | Easy Approach to Requirements Syntax. A structured format for expressing behavioral requirements used in design packages and plan phases. Each EARS statement is a traceable unit for QA coverage verification. | [../ecosystem/prompt-packages/meridian-dev-workflow.md](../ecosystem/prompt-packages/meridian-dev-workflow.md) |
| **Exact continue** | Resume of the same source harness session rather than a transcript fork or fresh-context launch. Exact continue preserves the source launch contract and rejects identity, policy, work, and task-dir mutations. | [../concepts/session-initiation.md](../concepts/session-initiation.md) |
| **Fork** | A harness capability allowing a new spawn to start from an existing session's state. Materialized via `fork.py:materialize_fork()`, the sole callsite for `adapter.fork_session()`. | [../concepts/harness-abstraction.md](../concepts/harness-abstraction.md) |
| **Ghost spawn** | Ambiguous legacy wording; do not use it as a canonical term. Older launch-boundary material used it for a **pre-worker stall** whose published row still exists. Issue #437 used “ghost spawn directory” for an **orphan artifact directory** whose row is gone. These states have opposite artifact-write rules. | **Pre-worker stall** and **Orphan artifact directory** below |
| **Harness bundle** | The registration unit for a harness: ties together an adapter class, spec class, extractor class, connection class, and `HarnessSemantics` port. Validated at registration time for duplicate IDs, extractor validity, connection compatibility, and semantics presence. | [../concepts/harness-abstraction.md](../concepts/harness-abstraction.md) |
| **Harness capabilities** | The `HarnessCapabilities` struct declaring what features a harness adapter supports: stream events, stdin prompt, session resume/fork, native agents, programmatic tools, primary launch, native file injection. | [../concepts/harness-abstraction.md](../concepts/harness-abstraction.md) |
| **Harness connection** | The abstract transport contract for communicating with a running harness. Concrete implementations: `claude_ws` (stdin/stdout stream-json), `codex_ws` (WebSocket JSON-RPC), `opencode_http` (HTTP + SSE). | [harness-adapters.md](harness-adapters.md) |
| **Harness extractor** | The protocol for session ID and report extraction from harness output artifacts. `StreamingExtractor` wraps a concrete extractor and prefers live connection session IDs over artifact-extracted ones. | [harness-adapters.md](harness-adapters.md) |
| **Harness ID** | The stable type identifying a harness (`HarnessId`). Values: `claude`, `codex`, `cursor`, `opencode`, `pi`. Distinct from `TransportId`, which identifies the underlying transport mechanism. | [../concepts/harness-abstraction.md](../concepts/harness-abstraction.md) |
| **Harness semantics** | Per-bundle `HarnessSemantics` port that normalizes open `RawHarnessEvent` envelopes into typed `EventSemantics` descriptors. Each adapter registers its own event-name to `EventSemantics` table and optional payload resolver. `normalize_event()` dispatches by `HarnessId` (bundle lookup), then by `event_type` within that table, returning `NormalizedHarnessEvent` carrying the raw event and its single descriptor. Each event is normalized exactly once. Shared `semantics.py` contains no harness event names. | [../concepts/harness-abstraction.md](../concepts/harness-abstraction.md) |
| **Heartbeat** | Deleted in identity-v2 PR 3 (v0.10.24). It was `spawns/<id>/heartbeat`, touched every 30 s, and the reaper treated a fresh one as proof of life. Spawn liveness is now whether the runner holds `launch.lock`. Old copies are inert; session archives still skip them. Do not confuse with `OutputSink.heartbeat`, a CLI progress message. | [../architecture/state-system/derived-status.md](../architecture/state-system/derived-status.md) |
| **Hook** | A handler that fires at a hook event: a spawn, work or notification moment (`spawn.finished`, `work.activated`, `notify.your_turn`, …). Can be a builtin (e.g., `git-autosync`) or a user-defined shell command. | [../concepts/hooks-and-plugins.md](../concepts/hooks-and-plugins.md) |
| **Hook context** | The hook invocation payload carrying event ID, spawn ID, status, agent, kind and error, work ID and directory, and the notification. Serialized as `MERIDIAN_*` env vars (`to_env()`) or JSON on stdin (`to_json()`). Schema version 3. | [../concepts/hooks-and-plugins.md](../concepts/hooks-and-plugins.md) |
| **Hook dispatcher** | The hook execution engine. Runs after store writes are complete. Dispatches in registry order and is fail-open: a failing hook is logged and the next one runs. | [../concepts/hooks-and-plugins.md](../concepts/hooks-and-plugins.md) |
| **Hook event spec** | One row of the `EVENTS` table (`EventSpec` in `lib/hooks/types.py`): an event's default timeout and the `when` fields it can supply. The only owner of per-event facts; replaced the observe/post/gate event classes. | [../decisions/hook-event-contract.md](../decisions/hook-event-contract.md) |
| **Hook registry** | The ordered registry of enabled hooks (`HookRegistry`). Sorted by source precedence rank, then negative priority, then declaration order. Disabled hooks are excluded from the event index. | [../concepts/hooks-and-plugins.md](../concepts/hooks-and-plugins.md) |
| **Interval tracker** | The hook throttling mechanism (`IntervalTracker`). Throttles hooks to run at most once per configured interval (e.g., `interval = "30m"`). Persists the last-run timestamp atomically per runtime root. | [../concepts/hooks-and-plugins.md](../concepts/hooks-and-plugins.md) |
| **Launch surface** | The `LaunchCompositionSurface` enum value controlling composition behavior. `PRIMARY`: full primary-path composition (session seed, inventory prompt). `SPAWN_PREPARE`: spawn path (prompt assembly from refs, context_from). `DIRECT`: test-only; skips policy resolution and trusts a pre-resolved request, and production `resolve_launch_policy` rejects it. | [../architecture/launch-system.md](../architecture/launch-system.md) |
| **Launch lock** | `spawns/pN/launch.lock`, an exclusive `flock` the runner holds from the row's publication to its exit (`state/launch_lock.py`, #647). Held means exactly "the runner is alive"; no harness holds the descriptor. A `--bg` parent hands it to its worker. | [../decisions/spawn-identity.md](../decisions/spawn-identity.md#pr-2-as-built-the-launch-lock-and-the-sweep) |
| **Launch-policy snapshot replay** | Resolving launch policy from a persisted `LaunchPolicySnapshot` instead of live config, environment, or Mars launch-bundle output. Exact continue uses this to preserve cache- and prompt-shaping launch fields. | [../decisions/launch.md](../decisions/launch.md#d-continue-replays-recorded-launch-contract-same-session-continue-is-not-live-policy-recomputation) |
| **Live budget tracker** | The runtime cost accumulator (`LiveBudgetTracker`). Tracks `run_cost_usd` (monotonically increasing) and `space_spent_usd`. `check()` enforces per-run and per-space limits. | [architecture/sandbox-projection.md](../architecture/sandbox-projection.md) |
| **Managed model override** | A model token Meridian passes to a harness. Absence means Meridian omits `--model` (or the harness equivalent) and the harness chooses its default. Persisted `LaunchPolicySnapshot.model == ""` is legacy JSON for this absence; in-memory replay uses `None`. | [../decisions/model-resolution.md](../decisions/model-resolution.md#model-optional-empty-model) |
| **Native task hold** | A completion hold caused by harness-owned background work. Claude native snapshots add blockers to the same candidate-scoped hold used for persisted descendants; this is evidence composition, not a separate completion policy. | [../architecture/drain-plans.md](../architecture/drain-plans.md#claude-native-holds) |
| **Meridian config** | The main settings model (`MeridianConfig`) loaded from TOML config files. Sections: `[defaults]`, `[timeouts]`, `[harness]`, `[primary]`, `[output]`, `[state]`. Loaded with source precedence: init args > env > local TOML > project TOML > user TOML. | [../concepts/config-precedence.md](../concepts/config-precedence.md) |
| **Locked mutation result** | `LockedMutationResult = Applied \| Declined \| Missing` — the discriminated return type from `write_state_locked()`. `Applied(before, after)` carries the atomic transition; `Declined(snapshot, reason)` carries the preserved state; `Missing` indicates the spawn did not exist. Mutators return `SpawnRecord \| Decline(reason)` to the repository. | [../architecture/spawn-finalization.md](../architecture/spawn-finalization.md) |
| **Operation runtime** | The per-call resolved context for ops layer operations (`OperationRuntime`). Fields: `project_root`, `config`, `harness_registry`, `artifacts`, `sink`. Built by `resolve_runtime_root_and_config()` and related helpers. | [../architecture/system-overview.md](../architecture/system-overview.md) |
| **Orphan artifact directory** | A `spawns/<id>/` remnant with no authoritative `state.json`. It is not a published spawn. Late writers must not recreate or extend it; retention and lock GC may remove its remnants. Historically called a “ghost spawn directory” in issue #437. | [../architecture/state-system/spawn-state.md](../architecture/state-system/spawn-state.md#published-spawn-artifact-lifetime) |
| **Allowlist (tools)** | A tool policy that permits only what it names. Whole-policy: a `*: deny` rule, which list-form `tools: [a, b]` produces. Per-capability: a capability whose only rules are scoped allows, such as `bash(rg *): allow` with no plain `bash` rule. Holds whatever `approval` says. | [../decisions/tool-permissions.md](../decisions/tool-permissions.md) |
| **Capability** | Mars's harness-neutral name for a group of tools in a profile's `tools` rules (`bash`, `edit`, `write`, `web`, `agent` for sub-agents, `task` for task-list tools). Mars maps each to the target harness's names; Meridian keeps no name table. | [../architecture/mars-launch-bundle.md](../architecture/mars-launch-bundle.md#tools-field) |
| **Enforcement report** | `EnforcementReport`: one `ReportLine` per permission-policy element with status `native`, `partial`, `unsupported` or `platform` and the native flag or setting used. Returned with the native projection by each harness's permission compile; shown in `--dry-run`, `permission_report` in `--json`, and the projection manifest. | [../decisions/tool-permissions.md](../decisions/tool-permissions.md) |
| **Permission policy** | `PermissionPolicy` (`safety/policy.py`): the frozen per-launch input to every harness's permission compile. Holds Mars's typed tool rules (with allowlists written as explicit denies), Meridian's platform rules, sandbox, approval, and the roots a native sandbox must leave writable. Built once at bind. | [../decisions/tool-permissions.md](../decisions/tool-permissions.md) |
| **Platform rule** | A permission rule Meridian adds regardless of the profile: the sub-agent deny, the spawn task-list deny, built-in agent denial, and the completion-command allow (`meridian spawn done`/`rearm`) on every spawn. Reported with status `platform`. | [../decisions/tool-permissions.md](../decisions/tool-permissions.md) |
| **Plugin API** | The stable Python API exposed to hooks and plugins (`meridian.plugin_api`). Owns the hook types and the `Notification` value that `lib/hooks` also uses, plus small helpers for state paths, config reads, git clone paths and file locking, shielding plugins from internal implementation changes. It carries no version of its own; the hook payload's `schema_version` identifies the hook contract. It does not deliver notifications; the built-in `notify` hook does. | [../concepts/hooks-and-plugins.md](../concepts/hooks-and-plugins.md) |
| **Primary event scope** | The harness-native identity that marks which streaming events belong to the parent spawn when the stream can also include child activity. Codex uses the main `threadId`; OpenCode uses the launched parent `sessionID`. Child events remain in history but do not complete, fail, clear signals for, or supply reports for the parent. | [../concepts/harness-abstraction.md](../concepts/harness-abstraction.md#event-semantics-and-terminal-outcomes) |
| **Pre-worker stall** | A still-published background spawn stuck between reservation/parent launch and detached-worker takeover. Launch-boundary observations exist to diagnose this state, so artifact writes remain valid while its row exists. Historical launch material called this a “pre-worker ghost.” | [../concepts/spawn-lifecycle.md](../concepts/spawn-lifecycle.md#reserve-before-prep-crash-window) |
| **Process launcher** | The abstract process launching interface (`ProcessLauncher`). Concrete implementations: `NativeProcessLauncher` (POSIX, inherited stdio), `PtyProcessLauncher` (POSIX PTY relay), `SubprocessProcessLauncher` (pipe capture / portable fallback), `WindowsConsoleLauncher`. Chosen by `select_process_backend()` from output capture and the resolved terminal surface mode. | [../architecture/primary-terminal-ownership.md](../architecture/primary-terminal-ownership.md) |
| **Project paths** | Project-scoped paths derived from the resolved project root and `meridian.toml`. Runtime state is distinct and user-local; repo-local `.meridian/` is not an active state root. | [../architecture/state-system/overview.md](../architecture/state-system/overview.md) |
| **Projection** | The harness-specific transformation of harness-agnostic semantic IR (`ComposedLaunchContent`) into concrete harness channel assignments (`ProjectedContent`). Performed by each adapter's `project_content()` method. | [../concepts/composition-pipeline.md](../concepts/composition-pipeline.md) |
| **PTY launcher** | The POSIX PTY relay (`PtyProcessLauncher`): inner PTY, raw stdin forwarding, output copy, resize bridge, teardown restore codes. Interactive Claude/Pi primaries use it by the owner's choice, not to read their output; Codex/OpenCode primaries do not. Also used for explicit output capture. Not used on Windows. | [../architecture/primary-terminal-ownership.md](../architecture/primary-terminal-ownership.md) |
| **Quarantine (spawn)** | Persisted spawn rows that cannot be interpreted. Single reads raise `SpawnStateQuarantined`; collection reads partition into `SpawnScan` (valid rows + `SpawnStateQuarantineReport` entries). Quarantined rows are never coerced to a default status. Migration, retention, and pruning fail closed on quarantine (quarantine = uncertain = keep). Known legacy v2 shapes are NOT quarantined — they upgrade through `state/spawn/legacy.py` first; quarantine applies to conflicting or truly unknown rows. | [../architecture/spawn-finalization.md](../architecture/spawn-finalization.md) |
| **Reconciliation** | Writing a terminal outcome for a dead launch. Since identity-v2 PR 3 only a holder of the spawn's `launch.lock` does it, through `finalize_dead_launch`, and it writes the outcome readers already derive. Readers never reconcile; terminal origin `reconciler` marks a reaper-written outcome. | [../architecture/state-system/derived-status.md](../architecture/state-system/derived-status.md) |
| **Reference item** | A file or directory passed to a spawn via `-f` / `--file`. Expanded at launch time into the prompt (files as full content, directories as tree listings). Template variable substitution (`{{KEY}}`) applies to reference contents. | [../concepts/composition-pipeline.md](../concepts/composition-pipeline.md) |
| **Resolved context** | The canonical immutable runtime context (`ResolvedContext`). Holds spawn ID, depth, project root, runtime root, chat ID, work ID, and resolved context directory paths. Used by launch, ops, and child env composition through one immutable seam. | [../concepts/context-resolution.md](../concepts/context-resolution.md) |
| **Runtime overrides (env)** | `$MERIDIAN_RUNTIME_DIR` (absolute or relative path to override the runtime root entirely) and `$MERIDIAN_HOME` (override the user root default). Used in tests and CI to isolate state. | [../concepts/state-model.md](../concepts/state-model.md) |
| **Runtime paths** | The user-level directory structure (`RuntimePaths`) under `~/.meridian/projects/<project-id>/`. Contains per-spawn `spawns/<id>/state.json`, `sessions.jsonl`, artifact dirs, hook state, telemetry, and cache. Keyed by the committed project ID so it survives repo renames. | [../architecture/state-system/overview.md](../architecture/state-system/overview.md) |
| **Sandbox** | The harness-native confinement of what a tool call that does run may touch on disk, set by sandbox mode. Separate from tool rules (which calls may run) and approval mode (when to prompt). Not every harness has one: OpenCode and Pi enforce none, and Claude's confines Bash only. | [architecture/sandbox-projection.md](../architecture/sandbox-projection.md), [../decisions/tool-permissions.md](../decisions/tool-permissions.md) |
| **Sandbox mode** | The permission tier applied to a spawn. Values: `default` (harness decides), `read-only`, `workspace-write`, `danger-full-access`. Mapped to harness-specific permission flags during launch. | [architecture/sandbox-projection.md](../architecture/sandbox-projection.md) |
| **Secret spec** | A frozen Pydantic model (`SecretSpec`) holding a secret key and value for redaction. Applied to stdout/stderr streams and artifact payloads. Sorted by length descending before substitution so overlapping secrets redact safely. | [architecture/sandbox-projection.md](../architecture/sandbox-projection.md) |
| **Session record** | The materialized session state (`SessionRecord`) produced by replaying session JSONL events. Holds session ID, start time, status, PID, and harness session ID. | [../architecture/state-system/session-state.md](../architecture/state-system/session-state.md) |
| **Spawn kind** | `SpawnKind`: `child`, `primary` or `streaming`. One literal owned by `plugin_api/types.py`; core lifecycle, persisted spawn state and hook `when.kind` all use it. | [../concepts/hooks-and-plugins.md](../concepts/hooks-and-plugins.md) |
| **Start gate / guardian** | Shipped (identity-v2 PR 1, #633, v0.10.13). Every harness starts as an `sh` stub that execs only after the runner records its process scope and writes `go` on a pipe. The stub leaves a double-forked **guardian** in the harness's process group; on pipe EOF (runner death) it kills the group, or sends the harness PID one SIGTERM in root-only mode. | [../decisions/spawn-identity.md](../decisions/spawn-identity.md#d-start-gate-guardian) |
| **Streaming extractor** | The extractor wrapper (`StreamingExtractor`) that prefers live connection session IDs and falls back to artifact/session detection. Wraps the concrete per-harness extractor. | [harness-adapters.md](harness-adapters.md) |
| **Template variable** | A `{{KEY}}` placeholder in prompt text or reference file contents, replaced at launch time via `--prompt-var KEY=VALUE`. Keeps variable content visible in prompt logs and dry-run output. | [../concepts/composition-pipeline.md](../concepts/composition-pipeline.md) |
| **Terminal facts** | `TerminalFacts` — frozen sub-model carrying finalized outcome: `exit_code`, `finished_at`, `published_at`, duration/token/cost metrics, `error`, and `origin`. Does not carry status; top-level `status` is the sole status authority. Nested under `SpawnStateFields.terminal`; terminal status requires `terminal is not None`, active status requires `terminal is None`. | [../architecture/spawn-finalization.md](../architecture/spawn-finalization.md) |
| **Terminal surface mode** | `TerminalSurfaceMode`: how an interactive primary's TUI meets the user's terminal. `NATIVE_INHERIT` (TUI inherits stdio; Codex, OpenCode) or `PTY_MEDIATED` (Meridian's PTY relay; Claude, Pi). Declared by the adapter; no user override; not persisted in launch-policy snapshots. | [../architecture/primary-terminal-ownership.md](../architecture/primary-terminal-ownership.md) |
| **Work activation** | The `work.activated` hook event: a user or agent chose a work item (`work start`, `work switch`, or a primary launch attaching `--work` / `--from` work), with or without a session. Child work inheritance, `work rename` and `work clear` update the attachment without activating. | [../decisions/hook-event-contract.md](../decisions/hook-event-contract.md#d-work-activation--activation-means-someone-chose-the-item) |
| **Runner exit facts** | `RunnerExitFacts` — frozen sub-model carrying the runner's resolved terminal intent: `status: TerminalSpawnStatus`, `exit_code`, `error`, `exited_at`. Nested under `SpawnStateFields.runner_exit`; presence (`runner_exit is not None`) is the reaper's authoritative guard. | [../architecture/spawn-finalization.md](../architecture/spawn-finalization.md) |
