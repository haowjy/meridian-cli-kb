# Vocabulary

Shared terminology contract for Meridian. Terms specific to one subsystem are defined on that subsystem's page.

When documentation uses a term, it means exactly what the relevant vocabulary page says. "See also" links point to the concept or architecture page covering the topic in depth.

## Core Terms

| Term | Definition | See also |
|---|---|---|
| **Adapter** | A harness-specific module that translates a generic `SpawnParams` struct into a concrete subprocess command (argv + env), and extracts session IDs, token usage, and reports from harness output. One file per harness; registered in `HarnessRegistry`. | [Harness abstraction](concepts/harness-abstraction.md) |
| **Ad-hoc place** | A project root without `meridian.toml` or `mars.toml`, plus the special user Mars root; Meridian derives a path-based identity and keeps its state outside the directory. | [Project identity](architecture/state-system/project-identity.md) |
| **Agent profile** | A YAML-fronted markdown file declaring a named agent: model, harness, skills, approval mode, sandbox, effort, fanout, and system prompt body. Loaded from `.mars/agents/` at launch time. Distinct from a skill. | [Model resolution](concepts/model-resolution.md#agent-profiles-and-prompting-guidance) |
| **Ask** | Any question the completion hold sends a child. The turn-end kind is the confirmation Codex and OpenCode keep; the expiry kind comes at the idle limit. "Nudge" is the wire word (`source="completion_nudge"`). A **wake** is the message that names a parent's unread finished children. | [Completion hold](architecture/completion-drain.md) |
| **Atomic write** | Crash-safe file write implemented as write to a temp file + fsync + rename. Used for replacement writes; append logs and directory publication have their own durability rules. | [Durability and locking](architecture/state-system/durability-and-locking.md) |
| **Bundled skill** | A skill whose subject is Meridian itself, shipped in the meridian-cli wheel as `<name>__meridian` (`notify__meridian`, `sessions__meridian`). Listed as one trigger line in every launch's `# Meridian skills` section and read with `meridian skills NAME`. Distinct from a package skill, which Mars installs from a prompt package. Meridian installs bundled skills into `.mars/skills/` with `mars provide`, where Mars calls them *provided skills* of provider `meridian`. | [Launch system](architecture/launch-system.md#skills-and-guidance) |
| **Capability** (package wording) | What prompt-package text names instead of Meridian syntax: "notify the human", "the work directory", "past sessions". Meridian's injected `# Meridian capabilities` section maps each to its command, so the same package reads naturally in runtimes without Meridian. Not the same as spawn capability (`has_spawn_capability`), which is whether a profile can delegate. | [Launch system](architecture/launch-system.md#skills-and-guidance) |
| **Chat owner** | The spawn that ran a chat: the newest session generation of the chat whose start event names a spawn that still has a row. A chat ID never means a child the chat launched. Spawn commands given a chat ID name the run live in the chat now, which can be a different run (one that moved in with native `/resume`), and fall back to the owner; `spawn message` accepts only the live run. A spawn ID always names that spawn, never its chat's owner. | [Spawn and chat references](concepts/session-references.md) |
| **Context** (two meanings) | Configured working-memory paths (the work directory, KB) or the composed launch context; the surrounding words distinguish them. Neither grants filesystem access; a workspace entry does. | [Work items and checkout links](architecture/state-system/work-items.md), [Workspace](architecture/workspace.md) |
| **Ghost spawn** (ambiguous) | Say which: a pre-worker stall has a published row; an orphan artifact directory has no row and must not be recreated by late writers. | [Spawn state](architecture/state-system/spawn-state.md) |
| **Capability** (tool policy) | In Mars tool policy, a harness-neutral group of tools. Distinct from package-wording capability and spawn capability above. | [Profile tool permissions](architecture/tool-permissions.md) |
| **Sandbox** | Confines what an allowed tool can touch. Tool rules govern which calls may run; approval governs when to prompt. | [Profile tool permissions](architecture/tool-permissions.md) |
| **Composition** | The process of assembling all launch-time inputs (prompt, skills, permissions, argv, env) into a `LaunchContext`. Performed exclusively by the prepare/bind pipeline in `lib/launch/context.py` (`prepare_launch_surface()` then `bind_launch_context()`). No driving adapter may re-derive what the pipeline already decided. | [Launch system](architecture/launch-system.md) |
| **Committed project** | A project root marked by `meridian.toml` or `mars.toml`, except the special user Mars root; its shared identity is the `[project].id` in `meridian.toml`. | [Project identity](architecture/state-system/project-identity.md) |
| **Crash-only design** | An architectural property: every write is atomic (tmp+rename), every read tolerates truncation, and recovery is startup behavior rather than a shutdown hook. Reads derive status without reaping; explicit or background repair persists outcomes and cleans up processes. | [State system](architecture/state-system/overview.md) |
| **Deprecation window** | The one minor release during which a removed or renamed config key, hook name or CLI flag still works and warns with its replacement; it becomes an error in the next minor release. | [Compatibility between builds](concepts/compatibility.md) |
| **Extension** | A named, surface-aware command unit declared as an `ExtensionCommandSpec`. Extensions are the single source of truth for all user-facing operations. The CLI and MCP server consume the same extension registry; there is no HTTP surface. | `src/meridian/lib/extensions/.context/CONTEXT.md` |

| **Format version** | An integer stored in data that another Meridian build, or a separately installed component, can read (`v` in telemetry, `sessions.jsonl`, `__status.json`, idle state). Readers check it against their supported set and refuse a newer value loudly; idle state is the exception. Distinct from semver, which versions installable software. | [Compatibility between builds](concepts/compatibility.md) |
| **Harness** | An external AI runtime Meridian adapts to run primaries and spawns: Claude, Codex, Cursor, OpenCode or Pi. Meridian is harness-agnostic: it never assumes which harness is in use. | [Harness abstraction](concepts/harness-abstraction.md) |
| **Hold** | What keeps a resident child open after a turn end, while work runs or until it is told to close. One value and one table in `hold_state.py`. Pi has its own profile and is not a hold. | [Completion hold](architecture/completion-drain.md) |
| **History ID** | A relocation-stable UUID identifying one portable transcript. Unlike runtime-local `pN` and `cN` aliases, it does not change across archive, import, restore, or local alias remapping. | [Portable history](architecture/state-system/portable-history.md) |
| **Idle limit** | How long a held child may go without work before it is asked once, `timeouts.resident_deadline_seconds`. Not `ActivityState`'s `"idle"`, which means a turn ended, and not `lib/idle/`, the primary-session idle timeline. | [Completion hold](architecture/completion-drain.md) |
| **Invariant** | A repo-wide constraint listed in the repository root `AGENTS.md`. | — |
| **JSONL** | The append-only log format used for session stores and chat event logs. Each line is one JSON event, and a line exists only once its newline is written: readers withhold a torn final line and skip malformed complete lines (archive receipts raise instead). One module, `state/jsonl.py`, owns the rule. Session state is derived by replaying from the beginning; spawn state lives in per-spawn `state.json`. | [State system](architecture/state-system/overview.md) |
| **Launch** | One run of a spawn. `--continue pN` reopens `pN` as its next launch, numbered `n` inside the row (`launch: {n}`), with its files in `spawns/pN/launches/<n>/`. The number is internal: it pins waits, cancels and delivery ledgers, and is never shown, typed or used as an identity. Its status comes from the runner-held `launch.lock` and a terminal written once. | [Spawn identity and launches](architecture/state-system/spawn-launches.md) |
| **Launch context** | The `LaunchContext` frozen dataclass produced by `bind_launch_context()`. Contains the full resolved launch state: argv, typed spec, env overrides, run params, permissions, child cwd, report output path, warnings, and resolved request. Complete and immutable at construction. | [Launch system](architecture/launch-system.md) |
| **Mars** | The standalone agent package manager (Rust CLI) that compiles source packages into `.mars/` for Meridian and emits skills to harness-native directories. Invoked via `meridian mars ...`. Owns model alias resolution. | [Package management](concepts/package-management.md) |
| **Message route** | What stands behind a session's control socket: a `MessageRoute` with one `deliver` call. A socket file means a route exists. | [Messaging a live session](architecture/primary-messaging.md#one-socket-for-every-primary) |
| **Native key** | The harness, actual native store/namespace, and native session ID that together identify one harness conversation. Each chat binds exactly one, immutably. A cwd, guessed file, or ID without its store is not a native key. | [Native session binding](architecture/native-session-binding.md) |
| **Precedence chain** | The resolution order applied independently to every config field: CLI flag > ENV var > agent profile > project config > user config > harness default. A CLI model override forces harness re-derivation from the overridden model, never from the profile's harness. | [Config precedence](concepts/config-precedence.md) |
| **Primary** | The top-level interactive agent launched directly by a human via `meridian` (without `spawn`). Has depth 0. Its chat ID is propagated to all descendant spawns as `$MERIDIAN_CHAT_ID`. Distinct from a spawn, which is a delegated child-agent task. | [Spawn lifecycle](concepts/spawn-lifecycle.md) |
| **Portable history record** | One readable JSONL transcript plus the file-backed identity, relationship, and recovery facts needed to transfer or reconstruct it. Loose files and verified immutable ZIPs are authority; SQLite is only a disposable projection. | [Portable history](architecture/state-system/portable-history.md) |
| **Prompt package** | A mars source package containing agent profiles, skills, and bootstrap docs. Compiled into `.mars/` by `mars sync` and copied to the harness directories a project lists as targets. Examples: `meridian-base`, `meridian-dev-workflow`, `meridian-prompter`. | [Prompt Packages Overview](ecosystem/prompt-packages/overview.md) |
| **Reaper** | `lib/state/reaper.py`. Persists the outcome of dead launches and cleans up their process scopes: it claims a stored-active row's free `launch.lock` and writes the outcome every reader already derives; a held lock means the runner is alive. Runs from `meridian doctor --kill-orphans` and as a bounded background pass of primary launches, only in a root process. Readers never call it. | [Derived spawn status](architecture/state-system/derived-status.md) |
| **Session** | A tracked conversation unit between Meridian and a harness. Identified by a chat ID (`c42`). Events are recorded in `sessions.jsonl`. The top-level primary session's ID is `$MERIDIAN_CHAT_ID`. | [Spawn lifecycle](concepts/spawn-lifecycle.md) |
| **Skill** | A markdown file of domain instructions or operational doctrine. An agent profile *loads* a skill (full text in the system prompt), lists it as *available* (named for the agent to load itself), or leaves it to harness discovery, which shows only `model-invocable` skills. Resolved by Mars from `.mars/skills/` at launch. Distinct from an agent profile. | [Skills](concepts/skills.md) |
| **Spawn** | A delegated child-agent task created by a primary agent or orchestrator via `meridian spawn`. Executed by a harness process, tracked in `spawns/<id>/state.json`, and associated with a spawn ID that `--continue` keeps. The core work unit in Meridian. | [Spawn lifecycle](concepts/spawn-lifecycle.md) |
| **State root** | The coordination boundary containing spawn/session/filesystem state. Committed `meridian.toml` `[project] id` anchors identity; mutable runtime lives under `~/.meridian/projects/<id>/` and default context under `~/.meridian/context/<id>/`. | [State system](architecture/state-system/overview.md) |
| **User config** (two files, plus a look-alike) | Say which one. Meridian's user config is `~/.meridian/config.toml` (or `MERIDIAN_CONFIG`), below the project's `meridian.toml`. The Mars user config is `$MARS_CONFIG_DIR/config.toml`, else `mars/config.toml` in the platform config directory (`~/.config/mars/config.toml` on Linux), the lowest Mars config layer: `config.toml < mars.toml < mars.local.toml < CLI`. The look-alike, the user Mars root `~/.meridian/mars/`, holds user *packages*, not settings. Bare "user config" means Meridian's. | [Package management](concepts/package-management.md), [Package management](concepts/package-management.md#user-scope) |
| **User Mars root** | The ordinary Mars project at `~/.meridian/mars/` that supplies user-scope packages, layered below project packages when supported. | [Package management](concepts/package-management.md#user-scope) |
| **Work item** | A named unit of work tracked as a directory under the context work root, with mutable metadata in `__status.json`. Has a title, status, description, and associated spawns. The active work item is the default attachment point for new spawns. Directory location determines active-vs-archived. | [State system](architecture/state-system/overview.md) |
