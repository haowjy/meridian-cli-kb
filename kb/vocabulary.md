# Vocabulary

Terms Meridian uses, and the ones easily confused. A term specific to one subsystem is defined on that subsystem's page. "See" links point to the page covering the topic in depth.

| Term | Meaning | See |
|---|---|---|
| **Ad-hoc place** | A directory with neither `meridian.toml` nor `mars.toml`, or the user Mars root. Its identity is derived from its path and Meridian writes nothing into it. | [Project identity](state/project-identity.md) |
| **Agent profile** | A markdown file with YAML frontmatter that declares a named agent: launch defaults (model, harness, skills, permissions) and its system prompt. Distinct from a skill. | [Model resolution](mars/model-resolution.md#agent-profiles-and-prompting-guidance) |
| **Ask** | Any question the completion hold sends a child: the turn-end confirmation Codex and OpenCode keep, or the one ask at the idle limit. "Nudge" is the wire word (`source="completion_nudge"`). A **wake** is the message that names a parent's unread finished children. | [Completion hold](spawns/completion-hold.md) |
| **Bundled skill** | A skill about Meridian itself, shipped in the meridian-cli wheel as `<name>__meridian`, listed as one trigger line in every launch and read with `meridian skills NAME`. Mars calls it a *provided skill* of provider `meridian`. Distinct from a package skill. | [Launch system](launch/launch-system.md#skills-and-guidance) |
| **Capability** (three meanings) | Say which. In package wording, what prompt text names instead of Meridian syntax ("the work directory"), mapped to commands by the injected `# Meridian capabilities` section. In Mars tool policy, a harness-neutral group of tools. Spawn capability (`has_spawn_capability`) is whether a profile can delegate. | [Launch system](launch/launch-system.md#skills-and-guidance), [tool permissions](permissions/tool-permissions.md) |
| **Chat** | A tracked conversation, named by a chat ID (`c42`) and bound to one native key. A primary's chat ID reaches its descendants as `$MERIDIAN_CHAT_ID`. "Session" in command names (`session log`) means a chat. | [Session state](state/session-state.md) |
| **Chat owner** | The spawn that ran a chat: the newest generation whose start event names a spawn that still has a row. Never a child the chat launched. | [Spawn and chat references](launch/session-references.md) |
| **Committed project** | A project root marked by `meridian.toml` or `mars.toml`, other than the user Mars root; its identity is the `[project].id` in `meridian.toml`. | [Project identity](state/project-identity.md) |
| **Context** (two meanings) | Configured working-memory paths (the work directory, the KB), or the composed launch context; the surrounding words tell them apart. Neither grants filesystem access; a workspace entry does. | [Work items](state/work-items.md), [workspace](permissions/workspace.md) |
| **Ghost spawn** (ambiguous) | Say which: a pre-worker stall has a published row; an orphan artifact directory has no row and must not be recreated by late writers. | [Spawn launches](state/spawn-launches.md) |
| **Harness** | An external AI runtime Meridian runs primaries and spawns in: Claude, Codex, Cursor, OpenCode or Pi. | [Harnesses](harnesses/overview.md) |
| **Hold** | What keeps a resident child open after a turn ends, while work runs or until it is told to close. Pi has its own profile and is not a hold. | [Completion hold](spawns/completion-hold.md) |
| **Idle limit** | How long a held child may go without work before it is asked once (`timeouts.resident_deadline_seconds`). Not `ActivityState`'s `"idle"`, which means a turn ended, and not `lib/idle/`, the primary-session idle timeline. | [Completion hold](spawns/completion-hold.md#waiting-has-one-number) |
| **Launch** | One run of a spawn. `--continue pN` reopens `pN` as its next launch. The launch number is internal: it pins waits, cancels and delivery ledgers, and is never shown, typed or used as an identity. | [Spawn launches](state/spawn-launches.md) |
| **Mars** | The agent package manager that compiles prompt packages into `.mars/` and harness-native files, and owns model aliases and routing. Invoked as `meridian mars ...`. | [Package management](mars/package-management.md) |
| **Message route** | What stands behind a session's control socket, delivering a `spawn message`. A socket file means a route exists. | [Messaging](spawns/messaging.md#one-socket-for-every-primary) |
| **Native key** | The harness, native store and native session ID that together identify one harness conversation. A chat binds exactly one, immutably; a cwd, a guessed file or an ID without its store is not a native key. | [Native session binding](state/native-session-binding.md) |
| **Portable history record** | One readable JSONL transcript plus the identity, relationship and recovery facts needed to move or rebuild it, identified by a history ID that survives archive, import, restore and alias remapping, unlike `pN` and `cN`. | [Portable history](state/portable-history.md) |
| **Primary** | The top-level interactive agent a human starts with `meridian` (no `spawn`). Distinct from a spawn. | [Primaries](launch/primaries.md) |
| **Prompt package** | A Mars source package of agent profiles, skills and bootstrap docs, such as `meridian-base`. | [Ecosystem](ecosystem.md) |
| **Sandbox** | Confines what an allowed tool can touch. Tool rules decide which calls may run; approval decides when to prompt. | [Tool permissions](permissions/tool-permissions.md) |
| **Skill** | Markdown instructions an agent profile *loads* (full text in the prompt), lists as *available* (named for the agent to load), or leaves to harness discovery. Distinct from an agent profile. | [Skills](mars/skills.md) |
| **Spawn** | A delegated child-agent run started with `meridian spawn`, keeping one spawn ID (`p42`) across continues. | [Spawn lifecycle](spawns/lifecycle.md) |
| **User config** (two files, plus a look-alike) | Say which. Meridian's is `~/.meridian/config.toml` (or `MERIDIAN_CONFIG`), below the project's `meridian.toml`. Mars's is `$MARS_CONFIG_DIR/config.toml`, else `~/.config/mars/config.toml` on Linux, the lowest Mars layer. The user Mars root `~/.meridian/mars/` holds user *packages*, not settings. Bare "user config" means Meridian's. | [Package management](mars/package-management.md#user-scope) |
| **Work item** | A named unit of work: a directory under the context work root, active or archived by where it sits. | [Work items](state/work-items.md) |
